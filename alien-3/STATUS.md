# Alien 3 (USA) — what is known, and the experiment behind each claim

ROM: `~/roms/dendy/nes/Alien 3 (USA).nes` (read in place, never copied). iNES: mapper 4 (MMC3),
8 × 16 KB PRG, 16 × 8 KB CHR. PRG offsets below are past the 16-byte header; "B<n>:$addr" is PRG
8 KB bank n seen at CPU $addr. The fixed bank at $C000-$FFFF is banks 14-15 (PRG $1C000-$1FFFF).

## 1. Getting into a level without playing

- **Path** (`src/path.ts`): Start held frames 700-703 skips the title's drawing, Start 824-827 picks
  "Start" on the menu; the level card (LEVEL n / MISSION / TRIES / GET READY) shows ~848-1150, the
  level is up by 1180. Proved by frames every 10/20 (runs/s3, regenerated by `src/shots.ts`).
  Start pressed earlier (frame 404) is ignored; on the half-drawn title (704) it only finishes it.
- **The level cell is `$A8`.** (`src/level-scan.ts`, then `src/level-poke.ts`)
  - Setting a cell on the menu changes no level (Start resets them): only menu options ($07A5,
    $07A7) and junk.
  - Set on the card (frame 900), of 794 cells read between card and level and holding ≤ 16, `$A8`
    = 1 and 2 changed the level's first screen (scan stopped after `$A8` was found: `$3F`, `$371`
    gave broken/menu screens, not levels).
  - `$A8` = 0..11 on the card loads 12 different levels (runs/level-poke/*.png, one each); the cell
    keeps the value. 12 = the size of the tables the loader indexes with it (§2).

## 2. The level loader (B15:$E9D5, fixed bank)

Read in the disassembly, every value confirmed by `src/who-writes.ts` (frame 1150, level 1:
writer pc and the ROM byte each RAM cell's value was loaded from):
- `LDY $A8`; `$C031,Y` → `$8A`/`$89` (PRG bank of the level's blocks, also put in R6);
  `$C03D,Y` → `$8B` (PRG bank of the layout). `$C019 + 2·$A8` → `$9E/$9F` = the level header.
- `$04..$26` ← header bytes `$0C..$2E` (LDA ($9E),Y; level 1: `$04/$05` = $832B from PRG $1F8C).

| $A8 | header | blocks bank $8A | layout bank $8B |
|---|---|---|---|
| 0 / 1 / 2 | $9F80 / $9FC0 / $9BC0 | 0 | 1 / 1 / 0 |
| 3 / 4 / 5 | same | 2 | 3 / 3 / 2 |
| 6 / 7 / 8 | same | 4 | 5 / 5 / 4 |
| 9 / 10 / 11 | same | 6 | 7 / 7 / 6 |

## 3. Who writes the play field (`src/vram-origins.ts`, `src/taint.ts`)

Nametable writes from the card to frame 2400, level 1, Right held from 1180 (taint: each value
followed back to the ROM through registers and RAM):
- **B15:$EF43** (`STA $2007` at $EF61 / $EF71) writes the field a column at a time ($2000 = $0C,
  +32): 22 rows, and 8 more when the address high byte ≥ $24, from the RAM buffer at `($3B)` =
  $0500. The values come from ROM bank 0 ($8300-$8BFF) — copied there by B15:$EB3F.
- B15:$F229..$F2D1, B6:$B36D: the status bar (digits from immediates, panel from bank 13).
- B15:$F31F/$F33A: from bank 0 $91C0-$92FF and RAM $0600 — not yet looked at.

## 4. Building a column strip (B15:$EB3F, $EB83)

- 8 blocks one under the other (`$46` bit 0 clear) or side by side (set), into $0500: 4 columns
  of 32 bytes.
- Block number: `LDA ($7E),Y` with R6 = `$8B` (layout bank); `$7E` = `$18/$19` + column, +$40
  for each block down — the layout is 64 blocks a row.
- Block's 16 tiles: `($04) + 16·block`, R6 = `$8A`, row-major 4 × 4 (scatter table $EBE0).
- Block's attribute byte: `($06),block` → `$3E`, stored at `($41)` (the attribute buffer).
